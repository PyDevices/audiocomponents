## 0. The specific risk this session was asked to test, and the verdict

The brief's named risk: "very few real units exist and they are famously
expensive, so check hard whether any 'CS-80' capture is actually a CS-80
rather than a CS-60, a CS-50, or a software emulation recorded to disk."

Tested directly this session, not re-asserted from the survey:

- The capture's own sound-page description, re-fetched this session,
  names the exact model twice: "Single note sampled from a **Yamaha
  CS-80** classic analogue synthesizer. I sampled all 61 notes for each
  of the **CS80** tone selector presets, and also the raw waveforms."
  (https://freesound.org/people/mogigrumbles/sounds/526634/, fetched this
  session). Nothing in the description, tags, or pack title hedges toward
  CS-60/CS-50/plugin.
- The uploader (`mogigrumbles`) is not an anonymous or single-upload
  account: a fresh search this session
  (https://freesound.org/people/mogigrumbles/packs/, and corroborating
  search-index hits) found **31 distinct sound packs**, every one titled
  after a real CS-80 factory tone-selector preset name — FLUTE, STRING 1,
  STRING 2, STRING 3, BRASS 2, BRASS 3, GUITAR 1, GUITAR 2, ORGAN 1,
  ORGAN 2, CLAVICHORD 2, HARPSICHORD 1, FUNKY 1, FUNKY 4, PULSE 75%,
  SQUARE, SINE, NOISE, PWM SLOW, BASS, ELECTRIC PIANO, and others — the
  CS-80's actual panel preset taxonomy, not a generic "CS80 patch 1/2/3"
  naming a plugin-only project would be more likely to use. This is a
  serious multi-preset, full-keybed sampling project (61 notes × many
  presets), internally consistent with a real hardware sampling session,
  not a single suspicious upload.
- The account belongs to a real, identifiable person: web search this
  session (query "Fract OSC soundtrack composer CS-80 synthesizer")
  surfaced the uploader's Bandcamp page
  (https://mogigrumbles.bandcamp.com/album/fract-osc-soundtrack) and
  confirms "Mogi Grumbles" is the professional name of **Alex Taam**,
  composer of the *Fract OSC* game soundtrack — matching the Freesound
  profile bio ("Electronic music producer/composer... OST for Fract
  OSC"). A working game composer with a shipped soundtrack credit is a
  materially different provenance class than an anonymous account.
- Checked for a contradicting or debunking discussion (forum skepticism,
  a "these are actually from a plugin" callout): a targeted search this
  session found none. Absence of a red flag is not proof, and is recorded
  as exactly that — absence, not confirmation.

**What this does not establish:** no photograph, video, or serial-number
evidence of the physical instrument was found or sought (none is
realistically obtainable for a Freesound upload from 2020). The gold call
rests on the stated provenance plus the corroborating signals above —
the same evidentiary bar this program has applied to every other capture
in the survey (e.g. `dmx`, `linndrum`, `tr808` all rest on a pack's own
stated provenance, not forensic verification). This is different in kind
from the `pianet`/`cp70` failures: those two had *positive, sourced

88-key vs. 73-key harp, the capture creator's own "impromptu and

looking for one.

## 1. Whether the hardware changed across its production life

Checked explicitly, since this is exactly the axis that dropped `pianet`
and `cp70`. Wikipedia's CS-80 article (CC BY-SA 4.0,
https://en.wikipedia.org/wiki/Yamaha_CS-80, fetched this session) and
Vintage Synth Explorer's CS-80 page (license unverified — site copyright
notice only, no terms-of-use text found;
https://www.vintagesynth.com/yamaha/cs-80, fetched this session) both
describe a single production run, 1976/77–1980, with no mention of a
second pickup technology, a resized keybed, or any other structural
revision analogous to the Pianet's electrostatic→magnetic pickup change
or the CP-70→CP-80 size change. (An earlier attempt to reach
`vintagesynth.com/yamaha/cs80`, without the hyphen, returned a 404 —
recorded as a dead link, not cited.) The capture and the literature
therefore belong to the same, single generation — there is no "which
generation" question to resolve for this instrument the way there was for
`pianet`/`cp70`.

## 3. What the machine is, mechanically

An 8-voice fully analog polyphonic synthesizer, each voice built from
**two** complete oscillator/filter layers — "8 times two patches," i.e.
16 VCOs total across the instrument (Vintage Synth Explorer, corroborated
independently by the search-aggregated spec line "16 VCO with multimode
filter with ring modulator," both fetched/read this session). Per-voice
signal path per the service manual's board list (§2) and the owner's
manual: independent low-pass and high-pass resonant filter stages
("independent hi pass and low pass resonant filters," VSE), a ring
modulator whose depth is set by an AC-voltage-controlled sub-oscillator
and whose rate is the sub-oscillator's own frequency (owner's manual p.47,
§2), and per-note envelope generators for both amplitude and filter. The
keyboard carries velocity and true **polyphonic aftertouch** — each key's
individual pressure is read independently, not a single global channel
pressure — plus a ribbon controller above the keys for pitch bend/filter
sweep. No structural revision across the production run was found (§1).

## 4. Hardware voice structure vs. the module

**Hardware:** 8-voice true polyphony; each voice carries 2 independent
oscillator layers (16 VCOs total), each layer with its own VCF; a shared
ring modulator per voice; per-note velocity and polyphonic aftertouch.
(Sources: Wikipedia and Vintage Synth Explorer, both §2.)

**Module:** `MAX_VOICES = 8` (`cs80.py:81`) — matches exactly. Each voice
is built from exactly 2 `synthio.Note` objects (`o1`, `o2`,
`cs80.py:118,121`), matching the 2-layer-per-voice architecture. Poly
aftertouch is wired: `EVENT_POLY_PRESSURE` scales each layer's amplitude
independently per held voice (`cs80.py:131-137`). A ring modulator is
applied identically to both layers via `ring_frequency`/`ring_waveform`
(`cs80.py:118,121`, driven by the `Ring Mod Speed`/`Ring Mod Depth` macros
at `cs80.py:9-13,144-145`).

**Structure verdict: matches.** No mismatch in either direction — same
outcome the survey already reported (`accuracy-survey.md:609`), now
independently re-confirmed against freshly-read sources rather than
carried over.

**One structural simplification worth flagging (read, not measured):**
the module does not give each layer both a low-pass *and* a high-pass
stage the way Vintage Synth Explorer's "independent hi pass and low pass
resonant filters" line describes. Instead it splits the two filter types
*across* the two layers — layer I (`o1`) gets only a low-pass Biquad
(`lp1`, `cs80.py:111,118`), layer II (`o2`) gets only a high-pass Biquad
(`hp2`, `cs80.py:112,121`), controlled by separate `VCF Cutoff` and `HPF
Cutoff` macros. If the real per-voice filter block is HP-then-LP in
series *within each layer* (as the phrasing suggests, though no schematic
page specific to the filter board was read closely enough this session to
confirm the exact topology — the SVU/PRA board designators in the service
manual's index, §2, are the likely home of that circuit and were not
individually opened this session), a more faithful rebuild would chain
both filter types on each layer rather than splitting them across layers.
This changes the character of `layer2_mix`: today it crossfades a
low-pass voice against a high-pass voice (two different timbres); on the
sourced description it should crossfade two independently-filterable
full-range voices. Flagged for whoever next opens the SVU/PRA schematic
pages, not resolved here.

## 6. What the module would need if rebuilt — read, not measured

Read from `cs80.py` only; nothing below was rendered or listened to this
session.

- **No audioif toolkit expansion is used today.** The entire signal path
  is built from bare `synthio` primitives (`Note`, `Biquad`, `LFO`,
  `Math`) — no `audiodynamics`, `audiofilters`, or `audioroute` node
  appears anywhere in the file (confirmed by reading the import block,
  `cs80.py:43-50`). A rebuild that wants the real per-voice VCA/limiting
  character, or a true parallel HP+LP filter chain per layer (§4), can
  reach for those nodes without needing a new toolkit capability — they
  already exist per the vision's §1 toolkit list.
- **The filter split across layers (§4) is the one concrete structural
  change a rebuild should evaluate** — replacing the current
  LP-on-layer-I/HP-on-layer-II split with an HP-then-LP chain on each
  layer, once the SVU/PRA schematic pages are actually opened and read
  (not done this session; the service manual's page index only was
  checked, §2).
- **No convolution is used**, so no `audioconvolve.FRAMES` latency
  applies to this instrument.
- `MACRO_LABELS` is at **16/16** already (`cs80.py:9-13`) — full. Any new
  control a rebuild wants (e.g. splitting the filter macros to expose
  both HP and LP per layer independently, per §4) would need to fold into
  an existing macro or a `" - lean"`/alternate patch rather than add a
  17th slot, per the roadmap's 16-macro ceiling.

## 7. MCU budget

Per-voice cost: 2 `synthio.Note` objects, 2 `Biquad` filters (one LP, one
HP), 1 shared filter-envelope `LFO` per note-on, 1 `Math` node for the
filter sweep, plus a ring-modulator waveform table when depth > 0.01
(`cs80.py:108-121`) — no wavetable larger than the default `make_table`
size, no convolution. This is comparable in weight to the other
8-voice-polyphonic synths already in the library (`jp8000`, `ppg_wave`,
`prophet_vs`); **no `" - lean"` patch is expected** on today's evidence,
and none was evaluated by measurement this session.
